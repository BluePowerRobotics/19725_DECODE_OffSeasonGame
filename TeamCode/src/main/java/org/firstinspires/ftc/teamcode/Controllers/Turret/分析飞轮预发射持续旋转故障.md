## 结论

这不是"按键冲突"，而是 **Turret 的发射状态机有一个永远出不去的状态，而"空闲"被错误地定义成"以预加速速度旋转"**。两个缺陷叠加，导致飞轮的目标速度一旦落入预加速通道就无法再被"发射开关"清成 0。

### 缺陷 1：`reset()` 把空闲速度写成 `preSpeed`，而不是 0

[Turret.java](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/Controllers/Turret/Turret.java#L347-L354)

```java
public void reset(){
    triggerServo.setPosition(HypParams.triggerResetPosition);
    ...
    shooter.setTargetVelocity(preSpeed);   // ← 空闲 = 预加速速度
    shootPhase = ShootPhase.IDLE;
}
```

`preSpeed` 就是预加速通道（P2 右扳机，[OffseasonDECODE_Red.java#L176](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/OpModes/OffseasonDECODE_Red.java#L175-L179)）算出来的值。于是 `reset()`（本意是"停止发射、回到空闲"）实际执行的是"停止自动发射，把飞轮交还给预加速通道"。**只要预加速通道仍有读数，飞轮就永远拿不到 0 目标**，此时发射开关（`shouldShoot`）对它已经没有任何控制权——这正是"不可控"的来源。

### 缺陷 2：`shootPhase` 卡在 `ACCELERATING`，状态机没有"发射完成"出口

[Turret.java](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/Controllers/Turret/Turret.java#L278-L312)

```java
case ACCELERATING: {
    aim(...);
    if (shooter.reachedVelocity()) {
        launch();                    // ← 只动舵机和标志位
        waitingForSpeed = false;
    }                                // ← 没有 shootPhase = IDLE
    ...
}
...
public void launch() {
    triggerServo.setPosition(HypParams.triggerLaunchPosition);
    isLaunching = true;
    lastLaunchTime = System.currentTimeMillis();
}
```

`launch()` 不把 `shootPhase` 置回 `IDLE`，所以下一帧又进 `ACCELERATING`：每帧重复 `launch()`、`isLaunching` 恒为 true（于是 `if (gamepad2.a) sweeper.setGiveArtifact()` 一直送球）、而飞轮目标被锁死在 IDLE 阶段算出的那个射速上。整个状态机唯一出口是 `shouldShoot == false`（[update 的 L376-384](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/Controllers/Turret/Turret.java#L376-L384)）。

### 完整因果链（数据不老实物）

1. 按住预加速键 → `preSpeed > 0`；此时 `shootPhase=IDLE`、`shouldShoot=false`，每帧走 else 分支 → `reset()` → `target = preSpeed` → 飞轮按预加速速度转，**看起来正常**。
2. 按自动发射键 → `shouldShoot=true` → `shoot()` 的 IDLE 分支：算距离、算射速、`setTargetVelocity(speed)`、`shootPhase = ACCELERATING`。
3. 之后**永久停在 ACCELERATING**：目标速度 = 自动射速，扳机舵机压在发射位，`isLaunching=true`。
4. 想停下来必须让 `shouldShoot=false` → 走 `reset()` → 目标写成 `preSpeed`。如果预加速通道还在激活（扳机仍有读数），飞轮继续转，发射键怎么按都无效；只有把预加速通道压到 0（或走反转/复位那种**绕过 preSpeed 赋值**的通路）才会恢复——这就是"只有按下全停键才正常"。

补充：即使 `preSpeed=0`，[Shooter.update() 在 target==0 时提前 return](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/Controllers/Turret/Shooter/Shooter.java#L96-L103)，既不刷新 `currentVelocity` 也不刷新 `lastUpdateTime`；电机又是 `FLOAT` 零功率行为，飞轮只是断电滑行而非主动刹停，遥测还会显示陈旧转速，视觉上就是"一直在转"。同时 `reachedVelocity()`（[Shooter.java#L92-L94](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/Controllers/Turret/Shooter/Shooter.java#L92-L94)）用"新目标 + 旧测量"比较，达速判断本身就不可靠。

### 附带的一致性问题

- 同一个 `targetVelocity` 有多个写入者（`shoot()`、`reset()`、反转分支、`update(kx)` 重载里那句无条件的 `setTargetVelocity(preSpeed)`），缺少单一的"停机"语义和优先级。
- 两套重载逻辑不一致：`update(boolean,...)`（[L360](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/Controllers/Turret/Turret.java#L360-L396)）与手动版 `update(double,double,int,boolean,int)`（[L448](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/Controllers/Turret/Turret.java#L448-L486)）的冷却/waitingForSpeed 顺序相反。
- 按键语义不统一：[Red 是 `gamepad2.aWasPressed()` 切换](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/OpModes/OffseasonDECODE_Red.java#L186-L191)、[Blue/FullTest 是长按 `gamepad2.a`](file:///d:/Github/19725_DECODE_OffSeasonGame/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/OpModes/OffseasonDECODE_Blue.java#L189-L200)；而 A 键同时被 sweeper 逻辑消费，`isShooting` 一旦卡在 true，只有 `forceLaunch()`（它会清 `shootPhase`）这类通路能解锁。

## 修复方向（未改动代码）

1. `reset()` 里改为 `shooter.setTargetVelocity(0)`。
2. `launch()` 后把 `shootPhase` 置回 `IDLE`（或引入 `COOLDOWN` 状态），让 ACCELERATING 不再每帧重复触发。
3. 预加速改成**显式**行为：在 update 的空闲分支里判断 `!shooting && !waitingForSpeed && preSpeed>0` 时再写 `preSpeed`，不要塞进 `reset()`。
4. `Shooter.update()` 在 `targetVelocity==0` 时也同步 `currentVelocity/lastUpdateTime`（顺带可考虑改 `BRAKE` 以便真正停住）。
